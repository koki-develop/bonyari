# 弓道場 (kyudo)

弓道場の射位に立って、28m 先の的へ矢を射る作品。

## 仕様として決まっていること

- 的中数・的中率・本数など、数字は一切出さない。
- 狙いは自分でつける。狙いを自動で補正しない。
- 矢は無限。射た矢は的・安土・芝などに残り続け、勝手には片付けない。片付けるのは右上のボタンを押したときだけで、押した瞬間に矢と的の穴が消える（矢は一瞬で薄れて消える）。片付けの演出（人が矢を取りに来るなど）は入れない。ユーザーが、待たされるのは不快だと判断した。
- 触れなければ何も射ない。自動で射る機能は入れない（ユーザーが不要と判断した）。
- 手元には弓と矢と弦だけを描く。腕や手は描かない（中途半端な作りの腕と手が不気味だとユーザーが判断した）。雀や赤とんぼのような小さな生き物の姿も描かない。生き物は声（共有の `WildlifeChorus`）だけ。
- 操作は、押して打起し → 下へ引いて引分け → 会（引き切った状態）で指を動かして狙う → 離して離れ。会の前に離すと弓を戻すだけ。キーボードでは Space の長押しと矢印キー。
- 会での見え方は「有明」: 弓の左に的が丸ごと見える。当たったところが弓に隠れないように。
- 当たりは静かに気持ちよく: 弦音 → 矢の飛ぶ間（約 0.58 秒）→ 28m 先から音が届くまでの遅れ（約 0.08 秒）→ 的の「パン」。残心のあいだ、目は矢の当たったところへ少し寄る。
- 1 日 = 実時間 15 分（`sim/world.ts` の `TIMEKEEPING`）。5 分では移り変わりが早すぎるとユーザーが判断した。新しい道場は 6:30 に始まる。
- 季節は秋だけ。毎日が同じ 11 月初めの一日（`sim/season.ts` の `TIME_OF_YEAR`）で、紅葉・舞う落ち葉・夜の秋の虫がそろう。太陽の通り道や日の長さもその日のまま。天気は晴れ・曇り・雨だけで、雪・雷雨・花びら・蛍・セミは無い。ユーザーが秋だけでいいと判断した。
- タブが隠れていても時間と音は止めない。10 秒ごとと、ページが隠れたときに `localStorage` へ保存する（`platform/store.ts`）。保存するのは時刻と天気、残っている矢、的の穴、自分の狙い。URL パラメータで場面を指定したとき（`seed` と、開発用のパラメータ）は、保存を読まず上書きもしない。

## アーキテクチャ

依存の向きは `sim/` ← `render/`、`sim/` ← `audio/` の一方通行。

- `sim/dojo.ts`: 近的の道場の寸法（射距離 28m、的の間隔 1.8m、的の中心 27cm で 5 度後傾、安土 1.5m、的場の軒 2m、射場の軒）と、それを組み立てる平らな形（`Quad` / `Box` / `Disc`）。矢の当たり判定も描画も、この同じ形を使う。的場の屋根は瓦の面・軒瓦・棟・両端の破風板、射場の軒は野地板と垂木まで形として持つ。瓦の丸みや重なりの段は形にせず、`render/scene.ts` で塗る。
- `sim/flight.ts`: 矢の弾道（線形の空気抵抗つきの放物線で、式で解ける）。`solveLaunch` は落ちる分を見越して、狙った点を通る向きを解く。`traceFlight` は道場の形と、立っている矢（筈に当たれば継ぎ矢、軸に当たれば弾かれる）との当たりを探す。
- `sim/arrows.ts`: 当たった矢の落ち着き方。紙を抜けて安土に刺さる、枠・幕・柱に当たれば落ちて地面に寝る、など。
- `sim/archer.ts`: 射手（`rest` / `draw` / `release` / `lower`）。命令（`begin` / `pull` / `nudge` / `loose` / `letDown`）で起きたことは、次の `update` のイベントとして報告される。
- `sim/world.ts`: 全体。共有の `Environment` に、道場の秋（`DojoSeason`: 舞う落ち葉と積もった落ち葉）を足して持つ。`clearArrows` で矢と穴を片付ける。保存に秋には無い天気が残っていたら、天気だけ引き直す。
- `render/`: 1 フレームの流れは、空 → 遠い山並み → 道場 → 木（奥から。道場に隠れきる木は描かない）→ 矢 → 雨や落ち葉などの粒 → 手元の弓と矢（`render/bow.ts`）。
  - 画面の解像度は、1 画素が CSS の約 2 ピクセルになるように決める（`render/layout.ts`）。スマホと同じ画素の細かさを大きな画面でも保つため。短い辺は 190〜300 画素に収め、上限で重さを抑える。短い辺を常に同じ画素数にすると、大きな画面では粗い画素が引き伸ばされ、的のドット絵だけが浮いて見える。
  - 道場は平面の部品だけなので、z バッファのラスタライザで描く（`render/raster.ts`）。画素ごとに部品・位置・向き・色を覚えておき（`render/scene.ts`）、カメラが整数画素だけ動いたときは中身をずらして、新しく見えた縁だけ描く。色は天気（濡れ具合）が変わると数行ずつ塗り直す。
  - 的は、画面での半径が 8 画素未満のあいだはトレースせず、ドット絵として描く（`drawTargetSprites`）。中心を画素にそろえ、白い中心点・黒い輪・白・黒い外帯を、どれも 1 画素以上の幅の丸い輪で描く。霞的の細い輪を正直に平均すると灰色の塊になり、画素の格子からずれた中心は 1 画素の模様を 2×2 ににじませる。中心を黒く塗りつぶした見え方は、本物と違うとユーザーが判断した。光は的の面の上で画素ごとに計算する。
  - 日なた（建物と木の影）と灯りは、平面ごとにワールド空間の格子で持つ（`render/atlas.ts`）。灯りは一度だけ計算し、日なたは太陽が動くたびに少しずつ更新する。
  - 矢と粒は `DepthSurface` の深度で、手前にある道場の部品に隠れる。共有の木も `Painter` 経由で同じ深度テストを通る。
  - 手元は景色とは別の焦点距離（`layout.bowFocal`）で描く。引くにつれて寄るのは景色だけで、手元は寄らない。手元の矢の線は、常に狙った点へ向かって収束する。
- `audio/`: 射手の音は射場の木の残響に、的場の音は距離に応じて遅く小さくする。矢を放った時点で当たる時刻と場所が決まっているので、当たりの音はそのとき予約する。正弦波（発振器）で音を組まない。電子音やレトロゲームの音に聞こえるとユーザーが判断した。叩かれて鳴る物（弓の竹、的の紙の太鼓、木、矢）は共有の `resonate`（`src/shared/audio/synth.ts`）で、雑音の一撃をその物の固有振動の帯域に通して作る。弦音は低い弦の物理モデル（Karplus–Strong の `pluck`）に、弦が弓を打つ音と竹の響きを重ねる。弾かれて落ちた矢は、跳ねる音ではなく、落ちた地面（砂・芝・砂利）に一端ずつ触れて止まる音にする（`bank.landing`）。同じ高さで間隔が縮むバウンドはコントのように聞こえるとユーザーが判断した。弓のきしみは連続音ではなく、握りと竹の微小なすべりを一粒ずつ鳴らす（`bank.slip`）。共鳴体の音は `normalize` で大きさをそろえ、鳴らすときの音量はエンジン側で決める。

座標系は x が右、y が上（矢道の地面から）、z が的の方向（射位から）。目は (0, 1.97, 0) にある。視線は北から 20 度西を向き、日中の太陽は射手の背中側から的を照らす。

## 守るべき不変条件

- 当たり判定と描画は `sim/dojo.ts` の同じ形を使う。寸法や形を変えたら、`sim/sim.test.ts` の弾道と当たりのテストで確かめる。
- 画素ごとのループの中ではメモリを確保しない。目安の負荷はデスクトップで、スマホの画面（195×422 画素）なら立っているとき・会のとき 4〜5ms、引分けや残心で景色が寄っていく間は 11ms 前後。PC の画面（500×285 画素ほど）では 5〜6ms と 24ms 前後。
- カメラの主点（`cx` / `horizon`）は整数画素に丸める（`render/rig.ts`）。丸めないと、狙いを動かすたびに道場を全部描き直すことになる。
- 保存する状態の形を変えたら、`sim/record.ts` の `FORMAT` を上げ、読み込みの検証もそろえる。
- 矢の数に上限はない。千本を超えても軽く描けるように、画面の外の矢は描かず、羽根が 1 画素に満たない矢は点で描く。

## 確認のしかた

開発サーバーでは URL パラメータで場面を指定できる: `seed`、`time`（`HH:MM`）、`weather`（`clear|cloudy|rain`）、`timescale`、`arrows`（その本数を自分の的のまわりに射た状態で始める）、`kai`（会のまま止める）、`aim`（`x,y`、的の面での狙い）。

- `window.kyudo` から `{ world, renderer, audio }` にアクセスできる。`world.handBegin()` / `handPull(1)` / `handLoose()` で射ることもできる。
- 音のバッファに NaN が混じると、マスターの後段が壊れてそれ以降すべて無音になる。音を作り直したら、全バッファの値が有限であることを確かめる。
- ヘッドレスのスクリーンショットは撮るたびにページが止まり、その間に世界が進む。離れから残心の画を撮るときは `timescale=0.2` などで遅くする。
- 28m 先の矢は小さい。的のまわりはデバイスピクセル比を上げて切り抜いて確かめる。
- `#start` を押せば `AudioContext` が動く。`audio.master` に `ScriptProcessorNode` をつなげば音の大きさを時刻つきで測れる。当たりの音は離れの約 0.66 秒後に来る。
