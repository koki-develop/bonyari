# 車窓 (train-window)

列車の窓から、終わりなく続く車窓を眺める作品。

## 仕様として決まっていること

- 暗転や終点は作らず、路線はシードから無限に生成し続ける。
- 1日 = 実時間5分、1季節 = 3日、1年 = 1時間（`sim/clock.ts`）。現実の時刻とは連動させない。新しい旅は 23:00、季節ランダムで始まる。
- 時刻はテーブルの上の小さなデジタル時計で `HH:MM` を1分単位で表示する。窓の上に時計は置かない。季節マークなどの飾りも添えない。
- 音はデフォルトでオン。iPhone のマナーモードには手を入れない（`navigator.audioSession` は設定しない）。
- 窓ガラスに車内を映り込ませない。ユーザーが明確に不要と判断した。
- 駅の人は動かさない。その場で立つか座るだけにする（歩いたり乗り込んだりする動きはユーザーが違和感ありと判断した）。
- 車内に落ちる外の光は、窓のすぐ外にある光源（トンネル照明・駅の蛍光灯・すれ違う列車・踏切）だけにする。遠くの建物や街灯の光は車内に届かない前提。
- タブが隠れていても旅と音は止めない。表示中は `requestAnimationFrame`、隠れている間はタイマーで世界を進める（`main.ts`）。90秒を超える空白（ページの凍結や端末のスリープ）は追いかけず、止まったところから続ける。
- 旅は10秒ごとと、ページが隠れたときに `localStorage` へ保存し（`platform/journey-store.ts`）、次に開いたときにそこから再開する。URL パラメータで場面を指定したとき（`seed`、開発用の `day` / `time` / `weather` / `section` / `only`）は、保存を読まず上書きもしない。
- 触れる要素は車内灯の切り替え（窓上のランプと右上のボタン）だけ。窓に息をかけたり指でなぞったりするギミックは、ユーザーの判断で削除した。

## アーキテクチャ

依存の向きは `sim/` ← `render/`、`sim/` ← `audio/` の一方通行。`render` と `audio` は互いに依存しない。

- `sim/`: DOM に依存しない決定的なシミュレーション（時計・天体・季節・天気・路線・列車・交通）。`World` が全体をまとめ、`World.update` は長い経過を `MAX_STEP` 刻みに分けて進める。刻みの間に起きたイベントは `World.trainEvents` / `strikes` / `bursts` に集まる。
- `sim/journey.ts`: 旅の保存形式。`World.snapshot()` で書き出し、`World.resume()` で続きから作り直す。
- `render/`: 低解像度のソフトウェアフレームバッファ（`core/surface.ts`）に描き、整数倍に拡大して表示する。1フレームの流れは、描くものを集める → 手前の不透明な層と山並みが、あとで塗りつぶすピクセルを `Cover` に記録する → 空 → 地面（ピクセルごとのレイキャスト。山並みの奥は `groundLimit` で描かない）→ 山並み・トンネルの山・景物・近景を横方向距離の遠い順に → 降水 → ガラス → 車内。山並みも景物と同じ列に並べるので、手前の物が山を隠し、山の奥の物は隠れる。トンネルの壁が視界をすべて覆うときは、その奥を丸ごと描かない。
- `audio/`: Web Audio のみ。単発音は起動時に `OfflineAudioContext` で合成しておき（`bank.ts`）、ループ音とイベントのスケジューリングは `engine.ts` が担う。鳥・カエル・虫の声（`wildlife.ts`）は種ごとに乱数から何通りも作り、同じ声が続けて鳴らないように選ぶ。

座標系は、`along`（線路沿いの m、画面右 = 進行方向）、`lateral`（線路からの横方向距離 m）、高さ（周囲の地面から m）。カメラは線路に垂直に外を向き、目の高さは線路の高さ + 2.3m（`render/camera.ts`）。空の向きは区間ごとの `Terrain.heading` で変わる。

## 守るべき不変条件

- 景物の配置とテクスチャは、ワールド座標とシードだけで決まる純粋関数にする。ハッシュは画面座標ではなく、ワールド座標の区画か建物ローカルのメートル座標から取る。フレームごとの乱数や時刻依存の出現判定を混ぜると、表示中の物が突然現れたり、スクロールで模様がちらついたりする。
- 近くを流れる繰り返し構造（電柱・トラス・枕木・すれ違う列車など）は、`pulseCoverage` / `intervalCoverage` と `cam.footprint()` で箱フィルタして描く。これがアンチエイリアスとモーションブラーを兼ねている。
- 色は `Shade` / `Painter` を通して、環境光と空気遠近を効かせる。発光するもの（窓明かり・街灯）は `lightRect` / `glow` で描く。立体の陰影（樹冠・幹・車体・人・壁面）は `Painter.surfaceLight` で面の向きから求め、太陽の側が明るくなるようにそろえる。
- 斜面の上に立つ景物（トンネルの山の木など）は `Scenery.base` に地面の高さを持たせる。
- 建物は `render/scenery/facade.ts` の部品で組み立てる。詳細度は1mあたりのピクセル数 `s` で段階的に落とす。
- 路線は列車の前後 45km まで生成しておく（`ROUTE_REACH`）。最遠の山並みは約 ±30km 先の地形を見るうえ、山の高さは一度計算すると区画ごとにキャッシュされるため、生成範囲が足りないと誤った稜線が残り続ける。
- 音のイベントは先読みで予約する。先読み幅は更新の間隔に合わせて伸ばす（隠れたタブではタイマーが間引かれる）。間に合わなかった継ぎ目や踏切の音は、まとめて鳴らさずに捨てる。`AudioContext` が停止している間はカーソルを現在位置に合わせ続け（`resync`）、再開した瞬間に溜まった音がまとめて鳴らないようにする。
- 再開した旅は、途中で保存しなかった場合とまったく同じに進む。路線は保持している最古の区間（`Route.anchor`）から作り直し、天気は乱数の位置まで持ち越す。列車や天気に持ち越す状態を足したら、`snapshot` / `restore` と `sim/journey.ts` の検証もそろえ、形が変わるなら `FORMAT` を上げる。`sim/sim.test.ts` の journey のテストで確かめる。
- 駅の停止はステップ後の位置で減速曲線に乗るよう陰的に積分している。変更したら `sim/sim.test.ts` で確認する。
- ピクセルごとのループの中ではメモリを確保しない。重い端末では1フレームおきに描画する仕組みがある（`main.ts`）。目安の負荷は、デスクトップで1フレーム 2〜5ms。
- `Cover` には、完全に不透明に塗る（被覆率がちょうど 1 の）ピクセルだけを、描画と同じ計算で記録する。記録を持つ層はトンネルの壁・防音壁と高架の床・ホーム・すれ違う列車・山並みで、描画と判定は同じ関数（`barrierColumn` / `platformHit` / `oncomingColumn` など）を共有している。これらの描き方を変えたら判定もそろえる。ずれると、奥の層が描かれずに前のフレームの絵が残る。
- 水面は空と地平線直下の行を映り込みとして読むので、見えている地面の近くでは、覆われていても空とその行は描く（`GroundRenderer.plan`）。

## 確認のしかた

開発サーバーでは URL パラメータで場面を指定できる：`seed`、`day`（0〜11）、`time`（`HH:MM`）、`weather`（`clear|cloudy|rain|storm|snow`）、`section`（最初の区間）、`only`（その区間だけを繰り返す）、`timescale`。

- `timescale=0.0001` で世界がほぼ止まるので、細部を撮るのに使える。
- `window.trainWindow` から `{ world, renderer, audio }` にアクセスできる。`world.train.pos` を書き換えれば、駅・トンネル・踏切・鉄橋の手前へ移動できる。
- `#start` を消すか押してから撮影する。ヘッドレスでも `#start` を押せば `AudioContext` が動くので、音量や音切れもマスター出力にアナライザーをつないで測れる。
